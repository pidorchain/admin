# VoidLauncher server

Профили лаунчера (ник + пароль), уникальные ID (новым выдаётся случайный 8-значный, админ может поставить любой от 1 до 99999999), значки (текст или картинка), баны и **админ-панель**. Всё хранится в SQLite.

## Запуск
Нужен Node.js 22.5+ (встроенный `node:sqlite`, зависимостей нет).

    ADMIN_PASSWORD='ваш-длинный-пароль' node server/server.js      # http://0.0.0.0:3000, база server/data/void.db
    PORT=8080 DB_PATH=/var/lib/void/void.db ADMIN_PASSWORD=... node server/server.js

Docker:

    docker build -t void-server server
    docker run -d -p 3000:3000 -v void-data:/data -e ADMIN_PASSWORD='ваш-длинный-пароль' void-server

Тесты: `cd server && npm test`

| Переменная | Значение |
|---|---|
| `ADMIN_PASSWORD` | пароль админ-панели, **не короче 10 символов**. Без него (или если он короче) панель выключена, в консоли будет сообщение |
| `PORT`, `HOST` | порт (3000) и адрес (0.0.0.0) |
| `DB_PATH` | путь к базе (`server/data/void.db`) |
| `TRUST_PROXY=1` | включайте за nginx/Caddy: лимиты считаются по реальному IP, cookie получает флаг `Secure` |

**Обязательно поставьте HTTPS** (например, Caddy или nginx + Let's Encrypt): по сети идут пароль администратора и пароли игроков.

## Админ-панель
Откройте `https://ваш-домен/admin` и введите `ADMIN_PASSWORD`.

- **Пользователи:** список, поиск по ID или нику, выдача значков, отзыв значков (✕ на значке), **смена ID** (свой от 1 до 8 цифр, например `7`, или случайный свободный) и **бан / разбан** с причиной.
- **Значки:** создание (название до 24 символов, иконка: эмодзи или символ, цвет) и удаление. При удалении значок пропадает у всех, кому он был выдан.
- Сессия живёт 8 часов (HttpOnly-cookie, SameSite=Strict), кнопка «Выйти» сбрасывает её сразу.
- Вход защищён от перебора: 5 неудачных попыток с одного IP блокируют вход на 15 минут (даже с верным паролем).
- Запросы на изменение данных принимаются только со служебным заголовком и с того же сайта (защита от CSRF). Все действия админа пишутся в консоль сервера (`[admin] ...`).

**Значки с картинкой.** На вкладке «Значки» нажмите «Загрузить картинку»: панель сама уменьшит её до 64×64 PNG (прозрачность сохраняется), и у игрока значок покажется с этой картинкой вместо иконки. Сервер принимает только PNG до 32 КБ.

**Бан.** Кнопка «Забанить» у пользователя (причина необязательна). Забаненный не может войти, зарегистрироваться по старому токену, а лаунчер показывает ему экран блокировки и не запускает игру и клиенты. Ник забаненного остаётся занятым. Бан привязан и к **устройству**: лаунчер присылает хеш ID машины (на Windows это MachineGuid, он не меняется при переустановке), сервер хранит его повторный хеш. После бана все устройства игрока блокируются, и новый профиль с этого компьютера создать не получится (в консоли `[admin] бан ... устройств: N`). «Разбанить» снимает всё; лаунчер подхватит это при ближайшей синхронизации (до 2 минут). Обойти бан по устройству можно сменой компьютера, переустановкой Windows (меняется MachineGuid), виртуальной машиной или правкой кода лаунчера. Полной защиты на стороне клиента не существует, ограничения только повышают порог.
- Хотите закрыть панель ещё сильнее? Ограничьте `/admin` по IP в nginx/Caddy или откройте её только через VPN.

**Смена ID.** Токены игрока, значки и вход по паролю переезжают на новый ID. Лаунчер игрока подхватывает новый ID сам: при запуске, при открытии вкладки «Профиль» и каждые 2 минуты. Старый ID освобождается и может достаться другому.

## API лаунчера
Все запросы `POST`, тело JSON. `token` — секрет установки, 64 hex-символа, его генерирует лаунчер.

- `/api/signup` `{ token, nick, password }` → `{ id, nick, createdAt, badges }` (201 новый профиль, 200 повтор). Ник: 3–16 символов `A-Za-z0-9_`, уникален без учёта регистра. Пароль: 6–64 символа. Ошибки: `bad_nick`, `bad_password`, `nick_taken` (409), `token_used` (409), `rate_limited` (429).
- `/api/login` `{ token, nick, password }` → `{ id, nick, createdAt, badges }`. Привязывает токен нового устройства к профилю. Ошибки: `bad_credentials` (401), `rate_limited` (429).
- `/api/me` `{ token }` → `{ id, nick, createdAt, badges }` (у значка есть `image`: PNG data-URL или `null`), 404, либо 403 `{ error: "banned", reason }`. По нему лаунчер обновляет ID и значки.
- `/api/register` `{ token }` → `{ id }`: анонимный ID без профиля (для старых версий лаунчера).
- `GET /api/users/:id` → `{ id, createdAt }` или 404.
- `GET /health`

`badges` — массив `{ id, title, icon, color }`.

## Безопасность
- Пароль игрока хранится как `scrypt` (N=16384, r=8, p=1) с отдельной солью, сравнение за постоянное время. Токены хранятся как SHA-256.
- Регистрации: до 20 в час с одного IP. Неудачные входы игроков: до 8 на ник и до 32 на IP за 15 минут.
- Страница админки отдаётся с `Content-Security-Policy` и `X-Frame-Options: DENY`; данные выводятся только через `textContent`, поэтому ник или название значка не могут внедрить код.
- Старые базы мигрируют автоматически: добавляются колонки ника, пароля, бана, картинки значка, а таблица пользователей пересоздаётся без ограничения «ID только из 8 цифр». Данные и сессии сохраняются.
- Делайте резервные копии файла базы (`void.db`, а при включённом WAL ещё `-wal` и `-shm`).

## Подключение лаунчера
Адрес сервера задаётся в `src/profile.js` (константа `API`, либо переменная окружения `VOID_API`). Замените `http://127.0.0.1:3000` на адрес вашего сервера перед сборкой.

## Бэкап базы в GitHub
Для хостинга без постоянного диска (Render Free): сервер сам сохраняет базу в **приватный** репозиторий GitHub и при старте, если файла базы нет, скачивает её обратно.

1. Создайте **приватный** репозиторий (например, `void-backup`): в базе лежат хеши паролей и токены.
2. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens: доступ только к этому репозиторию, право **Contents: Read and write**.
3. Добавьте переменные окружения сервера:

| Переменная | Значение |
|---|---|
| `GH_BACKUP_TOKEN` | токен из пункта 2 |
| `GH_BACKUP_REPO` | `владелец/void-backup` |
| `GH_BACKUP_PATH` | имя файла в репозитории (`void.db`) |
| `GH_BACKUP_BRANCH` | ветка (`main`) |
| `GH_BACKUP_INTERVAL_MIN` | как часто проверять изменения, минут (10) |

Без `GH_BACKUP_TOKEN` и `GH_BACKUP_REPO` бэкап выключен. Копия отправляется только если база изменилась, плюс при остановке сервера (SIGTERM). В консоли пишется `[backup] ...`. Если сервер упал без остановки, потеряется то, что произошло после последней копии (до `GH_BACKUP_INTERVAL_MIN` минут). Для постоянного диска (Render платный, VPS) этот бэкап не нужен, но как страховка он тоже годится.

## Защита бана
1. **Ключ подписи.** Выполните `node genkey.js` (в папке `server/`). Будет две строки:
   - `BAN_SIGN_KEY=...` добавьте переменной окружения на Render (секрет, никому не показывать и не коммитить).
   - `PUBLIC_KEY=...` вставьте в лаунчер: `src/profile.js`, константа `PUBKEY`. Он не секретный.
2. С этого момента сервер подписывает успешные ответы `/api/me`, `/api/login`, `/api/signup`, а лаунчер принимает «не забанен» только с верной подписью (с одноразовым `nonce` и временем). Поэтому бан нельзя снять правкой `launcher.json`, подменой адреса сервера (`VOID_API`) или файлом `hosts`.
3. Если ключ в лаунчере задан, игра запускается, только если сервер успешно проверял профиль за последние `MAX_OFFLINE_H` часов (по умолчанию 72, значение в `profile.js`; 0 отключает). Так бан не обойти, просто отрезав лаунчеру интернет.
4. `REQUIRE_HWID=1` (необязательно): сервер отклоняет регистрацию и вход без ID устройства. Включайте, когда все игроки перешли на новую версию лаунчера: старые версии его не присылают.

**Порядок выкладки:** сначала обновите сервер на Render, потом выпустите новую версию лаунчера (с `PUBKEY`). Включайте `BAN_SIGN_KEY` до выхода лаунчера с `PUBKEY`, иначе ответы будут без подписи, и лаунчер перестанет принимать профиль.
