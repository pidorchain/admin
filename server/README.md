# VoidLauncher server

Профили лаунчера (ник + пароль), уникальные 8-значные ID (10000000–99999999), значки и **админ-панель**. Всё хранится в SQLite.

## Запуск
Нужен Node.js 22.5+ (встроенный `node:sqlite`, зависимостей нет).

    ADMIN_PASSWORD='ваш-длинный-пароль' node server/server.js      # http://0.0.0.0:3000, база server/data/void.db
    PORT=8080 DB_PATH=/var/lib/void/void.db ADMIN_PASSWORD=... node server/server.js

Docker:

    docker build -t void-server server
    docker run -d -p 3000:3000 -v void-data:/data -e ADMIN_PASSWORD='ваш-длинный-пароль' void-server

Тесты: `cd server && npm test`

| Переменная | Значение |
|---|---|
| `ADMIN_PASSWORD` | пароль админ-панели, **не короче 10 символов**. Без него (или если он короче) панель выключена, в консоли будет сообщение |
| `PORT`, `HOST` | порт (3000) и адрес (0.0.0.0) |
| `DB_PATH` | путь к базе (`server/data/void.db`) |
| `TRUST_PROXY=1` | включайте за nginx/Caddy: лимиты считаются по реальному IP, cookie получает флаг `Secure` |

**Обязательно поставьте HTTPS** (например, Caddy или nginx + Let's Encrypt): по сети идут пароль администратора и пароли игроков.

## Админ-панель
Откройте `https://ваш-домен/admin` и введите `ADMIN_PASSWORD`.

- **Пользователи:** список, поиск по ID или нику, выдача значков, отзыв значков (✕ на значке) и **смена ID** (свой 8-значный или случайный свободный).
- **Значки:** создание (название до 24 символов, иконка: эмодзи или символ, цвет) и удаление. При удалении значок пропадает у всех, кому он был выдан.
- Сессия живёт 8 часов (HttpOnly-cookie, SameSite=Strict), кнопка «Выйти» сбрасывает её сразу.
- Вход защищён от перебора: 5 неудачных попыток с одного IP блокируют вход на 15 минут (даже с верным паролем).
- Запросы на изменение данных принимаются только со служебным заголовком и с того же сайта (защита от CSRF). Все действия админа пишутся в консоль сервера (`[admin] ...`).
- Хотите закрыть панель ещё сильнее? Ограничьте `/admin` по IP в nginx/Caddy или откройте её только через VPN.

**Смена ID.** Токены игрока, значки и вход по паролю переезжают на новый ID. Лаунчер игрока подхватывает новый ID сам: при запуске, при открытии вкладки «Профиль» и каждые 2 минуты. Старый ID освобождается и может достаться другому.

## API лаунчера
Все запросы `POST`, тело JSON. `token` — секрет установки, 64 hex-символа, его генерирует лаунчер.

- `/api/signup` `{ token, nick, password }` → `{ id, nick, createdAt, badges }` (201 новый профиль, 200 повтор). Ник: 3–16 символов `A-Za-z0-9_`, уникален без учёта регистра. Пароль: 6–64 символа. Ошибки: `bad_nick`, `bad_password`, `nick_taken` (409), `token_used` (409), `rate_limited` (429).
- `/api/login` `{ token, nick, password }` → `{ id, nick, createdAt, badges }`. Привязывает токен нового устройства к профилю. Ошибки: `bad_credentials` (401), `rate_limited` (429).
- `/api/me` `{ token }` → `{ id, nick, createdAt, badges }` или 404. По нему лаунчер обновляет ID и значки.
- `/api/register` `{ token }` → `{ id }`: анонимный ID без профиля (для старых версий лаунчера).
- `GET /api/users/:id` → `{ id, createdAt }` или 404.
- `GET /health`

`badges` — массив `{ id, title, icon, color }`.

## Безопасность
- Пароль игрока хранится как `scrypt` (N=16384, r=8, p=1) с отдельной солью, сравнение за постоянное время. Токены хранятся как SHA-256.
- Регистрации: до 20 в час с одного IP. Неудачные входы игроков: до 8 на ник и до 32 на IP за 15 минут.
- Страница админки отдаётся с `Content-Security-Policy` и `X-Frame-Options: DENY`; данные выводятся только через `textContent`, поэтому ник или название значка не могут внедрить код.
- Старые базы (только ID) мигрируют автоматически: добавляются колонки ника, пароля, таблицы значков.
- Делайте резервные копии файла базы (`void.db`, а при включённом WAL ещё `-wal` и `-shm`).

## Подключение лаунчера
Адрес сервера задаётся в `src/profile.js` (константа `API`, либо переменная окружения `VOID_API`). Замените `http://127.0.0.1:3000` на адрес вашего сервера перед сборкой.
